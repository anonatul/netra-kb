## AD-001 — Modular Monolith for MVP

**Decision:** One deployable backend with clearly separated internal modules.

**Reason:** The dominant problem is proving operational intelligence, not distributed systems. Faster dev, simpler demo, easier offline deployment.

**Status:** ✅ DECIDED. Revisit: only when load profiling justifies microservices (NLP / ingestion scaling).

## AD-002 — PostgreSQL + PostGIS

**Decision:** Primary database; spatial indexes (GIST) on locations/zones.

**Reason:** NETRA is inherently spatial and transactional.

**Status:** ✅ DECIDED.

## AD-003 — One Queue Mechanism Only

**Decision:** Simplest reliable async mechanism (lightweight task queue / database-backed jobs / Redis). NO Kafka, NO Kafka+RabbitMQ duality.

**Reason:** A few thousand simulated events don't need distributed event architecture. Kafka only if load testing justifies it.

**Status:** ✅ DECIDED.

## AD-004 — Rescue Priority Score as the Core Innovation

**Decision:** The central artifact is a transparent, explainable priority model (severity, victim count, vulnerability, recency, confidence, accessibility) — not DBSCAN, not AI, not the dashboard.

**Reason:** Judge verdict: "AI + DBSCAN + dashboard isn't sufficient innovation." The priority engine is the defensible decision layer.

**Status:** ✅ DECIDED — highest development priority.

## AD-005 — Adaptive (Uncertainty-Aware) Clustering

**Decision:** Cluster radius depends on GPS accuracy, source, density, disaster type. NOT a fixed 50m.

**Reason:** "Why 50m?" destroys a fixed-radius claim. High-accuracy GPS → 20–30m; poor cell location → 100–300m; urban dense → smaller; rural flood → larger.

**Status:** ✅ DECIDED.

## AD-006 — Three-Layer AI

**Decision:** Layer 1 deterministic safety rules (always on) → Layer 2 lightweight multilingual classifier → Layer 3 optional LLM (off critical path, human-review queue on failure).

**Reason:** AI only where it materially beats rules; LLM failure must never suppress an emergency.

**Status:** ✅ DECIDED.

## AD-007 — Human-in-the-Loop

**Decision:** AI detects → AI explains → dispatcher verifies → dispatcher assigns → field executes. No autonomous dispatch, no auto-resolved incidents.

**Reason:** Government adoption, accountability, safety.

**Status:** ✅ DECIDED.

## AD-008 — Connectivity State Machine

**Decision:** NORMAL → DEGRADED → SEVERELY DEGRADED → CELLULAR UNAVAILABLE → LOCAL/ALTERNATIVE NETWORK. Each state defines available ingestion sources.

**Reason:** Avoids the false "works with zero cellular infrastructure" claim; makes degradation explicit.

**Status:** ✅ DECIDED (see file 14).

## AD-009 — Local-First Deployment / Demo

**Decision:** Everything runs locally on one machine (frontend, backend, DB, workers, NLP, simulation). No live internet / external API dependencies.

**Reason:** Demo reliability; "NETRA works because the system is under our control."

**Status:** ✅ DECIDED.

## AD-010 — Adapters + Common Event Model

**Decision:** External sources (ERSS, SACHET, ELS, SMS, field, simulation) connect through adapters producing one NETRA event model.

**Reason:** Prevents hard-coded government dependencies; simulates integration for MVP.

**Status:** ✅ DECIDED.

## AD-011 — Rule-Based Resource Recommendations First

**Decision:** Explainable rules ("flooded + road blocked + victims > threshold → consider boat") before any AI recommendation.

**Reason:** Explainability, validation, predictable behavior.

**Status:** ✅ DECIDED.

## AD-012 — Incident (Not Message) as Central Object

**Decision:** Model around Incidents with many evidence sources, not message → map pin.

**Reason:** Incident fusion is the operational core; enables independent-source counting and evidence confidence.

**Status:** ✅ DECIDED.

## AD-013 — No Custom Telecom / No Femtocell in MVP

**Decision:** Complete-blackout / femtocell / drone portable-network capability is EXPLICITLY out of MVP scope and not claimed.

**Reason:** Judge: "architecture fantasy without a telecom partner and validated prototype."

**Status:** ✅ DECIDED (see file 26).

## AD-014 — Benchmark vs Baselines

**Decision:** Every claim measured against manual triage / raw count / simple rules.

**Reason:** The gap between screening (78) and winning (55) is evidence.

**Status:** ✅ DECIDED — experiment plan in file 19.

## Golden Decision Rule

> **Reject any architecture choice that adds complexity without a measured requirement.**
