## 1. Why This Matters (Judge Feedback)

NETRA handles highly sensitive data:

- phone numbers
- precise victim locations
- medical conditions
- emergency status
- potentially household information

Security score is currently **5/10**; target is **8/10**. This section is the action plan.

---

## 2. Adversarial Questions A Judge May Ask

| Question | Answer must show |
| -------- | ---------------- |
| Who can see this data? | Authentication + RBAC + access audit |
| How long is it retained? | Configurable retention policy aligned with law |
| Can an attacker inject 10,000 fake victims? | Source validation + rate limiting + anomaly detection |
| Can someone create fake red zones? | Independent-source count + confidence scoring |
| Can criminals track vulnerable populations? | Location access restricted by role, PII minimization |
| What if the dashboard laptop is stolen? | Offline encrypted storage + device controls + remote revocation |

---

## 3. Data Classification

| Class | Example | Protection |
| ----- | ------- | ---------- |
| PII | phone numbers, names | Minimize, pseudonymize, encrypted storage |
| Precise location | victim coordinates | Role-restricted access, confidence radius in public views |
| Medical/sensitive | medical emergencies, vulnerability | Strictly authorized access, audit logs |
| Operational | incident state, priority | Authorized responder access |
| Audit | who did what | Append-only, protected from modification |

---

## 4. Controls (MUST for MVP)

```text
Authentication           → no anonymous operational access
Role-based access        → OPERATOR / COMMANDER / FIELD / ADMIN / AUDITOR
Least privilege          → only permissions needed for the role
HTTPS / TLS              → no plaintext app transport
Encryption at rest       → sensitive stored data
Audit logs               → login, access, override, verification
Input validation         → text, coordinates, identifiers, API payloads
Rate limiting            → prevent abuse / overload
Data minimization        → keep only what operations require
Retention policy         → configurable, law-aligned
Secure sessions          → expiration, revocation
Fail-closed              → invalid auth = denied, never anonymous fallback
```

---

## 5. Abuse / Fake-Report Defense

```text
Unique devices vs message count     → 84 messages ≠ 84 victims
Independent-source count            → prevents one source faking a crisis
Spatial/temporal pattern analysis   → detects coordinated fake SOS bursts
Source reliability metadata         → field verification > unverified citizen
Anomaly flagging                    → suspicious patterns surfaced to humans
```

A naive heatmap shows "MASSIVE CRISIS" from 500 fake SOS; NETRA must reduce confidence and flag the pattern.

---

## 6. Monitoring Without PII Leakage

Logs and monitoring dashboards must not expose:

- phone numbers
- personal names
- precise victim details

Redact or pseudonymize sensitive fields in logs.

---

## 7. Offline Security

Offline command-center mode still requires:

- local authentication
- encrypted local storage
- restricted physical access
- sync authenticated when connectivity returns

"Offline" must never mean "anyone can read the laptop."

---

## 8. Security Testing (MVP)

At minimum test:

- unauthorized access attempts
- invalid authentication
- role escalation
- injection attempts
- malformed payloads
- exposed secrets
- insecure API endpoints

---

## 9. Golden Security Rule

> **Security failures fail closed. Emergency data access is never anonymous, never unlogged, and never retained longer than policy allows.**
