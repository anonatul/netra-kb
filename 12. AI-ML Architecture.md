# 12. Rescue Priority Engine

# NETRA — AI/ML Architecture

## 1. Purpose

Define where AI/ML is used in NETRA, why it is needed, and how the system behaves when AI fails.

Core principle:

> AI is an assistive component, not the core product and never a single point of failure.

---

## 2. AI Components

Potential AI/ML capabilities:

- Multilingual text understanding
- Incident attribute extraction
- Severity extraction
- Vulnerability detection
- Location/entity extraction
- Semantic similarity for duplicate detection

---

## 3. AI Pipeline

Raw Message
    ↓
Language Detection
    ↓
Text Normalization
    ↓
NLP Model
    ↓
Structured Attributes
    ↓
Confidence
    ↓
Incident Processing

Example:

"Grandmother cannot walk, water entered house."

↓

```text
Flood = YES
Elderly = YES
Mobility limitation = YES
Potentially trapped = YES
Severity = HIGH
Confidence = 0.91
```

---

## 4. AI Decision Rule (Judge-Critical)

AI is justified **only** when it materially beats a rule-based baseline on a measured metric.

```text
If Rules: 91% F1  vs  AI: 92% F1  → AI not justified (10× cost)
If Rules: 65% F1  vs  AI: 89% F1  → AI justified
```

Do not use AI for:

- simple keyword detection (`bleeding → medical-critical`)
- deterministic status processing
- basic database/geospatial operations

Use AI for:

- **unstructured multilingual distress → structured incident attributes** (victim count, medical urgency, vulnerability, water level, trapped status)
- semantic similarity for duplicate detection
- location/entity extraction from free text

---

## 5. Three-Layer AI Strategy

### Layer 1 — Deterministic safety rules (always on)

```text
bleeding        → medical-critical
trapped         → rescue-required
elderly         → vulnerability+
pregnant        → vulnerability+
water rising    → escalation
safe            → close candidate
```

High-confidence, explainable, zero-latency, auditable.

### Layer 2 — Lightweight multilingual classifier

Structured extraction for English + Hindi + Hinglish (MVP; extend later).

### Layer 3 — Optional LLM (off critical path)

Only for difficult/unstructured reports that layers 1–2 cannot resolve.

---

## 6. LLM Safety Rule

> **LLM failure must never suppress an emergency.**

```text
AI failed / unknown classification
              ↓
      HUMAN REVIEW QUEUE
```

NOT:

```text
AI failed
    ↓
ignore report
```

LLM output = evidence, not truth. Every output carries:

```text
Prediction
+ Confidence
+ Model Version
```

---

## 7. AI Failure Fallback

```text
NLP unavailable
      ↓
Rule-based extraction (Layer 1)
      ↓
Reduced-confidence result
      ↓
Human review where necessary
```

Emergency workflow must continue without AI.

---

## 8. Model Isolation

AI inference sits behind an interface:

```text
NLPInterface
    ↓
RuleBasedExtractor
    OR
ML/Transformer Extractor
    OR
Optional LLM Extractor
```

The rest of NETRA does not care which implementation is active.

---

## 9. Evaluation Requirements

Every AI capability must have a metric on a labelled dataset:

```text
Severity classification   → precision / recall / F1
Vulnerability detection   → precision / recall / F1
Victim count extraction   → precision / recall / MAE
Location extraction       → exact match / distance error
Duplicate detection       → precision / recall / F1
```

No unvalidated accuracy claims ("95% accurate") without dataset + metric + method.

---

## 10. Human Confirmation

```text
AI detects
    ↓
AI explains
    ↓
Dispatcher verifies
    ↓
Dispatcher assigns
    ↓
Field team executes
```

AI is decision support, not an autonomous emergency commander.
