## 1. Demo Principle

Do NOT demo "here's a map." Demo **the decision problem being solved**: signals → prioritized rescue zones → responder action.

Everything runs locally. No dependency on:

- live internet
- unverified government APIs
- external AI/LLM APIs
- live telecom integration

## 2. The Killer Demo (Judge-Recommended)

Simulated flood scenario:

### Minute 0

Dashboard: 0 incidents. Disaster context activated.

### Minute 2

50 reports arrive (multilingual, some duplicates, some noise).

NETRA produces:

```text
50 reports
→ 17 incidents
→ 6 zones
→ 2 P1, 3 P2, 1 P3
```

### Minute 4

30 more reports; one area now shows elderly + child + bleeding + rising water.

NETRA recalculates:

> **ZONE 4 → P1**

Recommendation: 2 boats + medical response, with reasons.

### Minute 5

Field officer marks zone:

> **RESCUED**

Incident remains in history but leaves the active priority queue.

### Demo punchlines

- priority is not report count (Zone with fewer victims but critical conditions ranks P1 over a larger safe zone)
- explainable priority reasons
- independent evidence count (84 messages ≠ 84 victims)
- uncertainty shown as confidence radius, not exact pins

## 3. Adversarial Demo (Optional but Impressive)

- 500 fake SOS from one location → NETRA reduces confidence, flags anomaly
- 30 duplicates from one device → counted as one source
- connectivity cut → dashboard switches to OFFLINE mode, keeps working
- AI service killed → rule fallback continues processing

## 4. Deterministic Scenario Replay

The demo must be reproducible:

```text
T+00: 20 reports
T+05: 80 reports
T+10: building collapse report
T+15: field verification
```

Same input → same demo output. Prevents "the AI behaved differently during judging."

## 5. Demo Recovery Script

Team must be able to recover mid-demo from:

- backend restart
- browser refresh
- temporary network loss
- model service failure

## 6. What the Judge Should See

> **"NETRA works because the system is under our control"** — local, deterministic, recoverable.

## 7. Golden Demo Rule

> **Show the decision improving, not the dashboard shining.**
