## 1. Data Principle

> **Raw evidence, derived intelligence and human decisions must remain distinguishable and traceable.**

```text
RAW:      Citizen says "water up to waist"
DERIVED:  Water level = HIGH
SYSTEM:   Priority = P1
HUMAN:    Commander confirms P1
```

## 2. Core Data Objects

```text
Disasters
Events (raw incoming observations)
Evidence (source-linked, provenance preserved)
Incidents (consolidated representation, many events → one incident)
OperationalZones
PriorityScores (versioned)
Recommendations (explainable)
FieldUpdates
Users / Roles
AuditLogs
ModelVersions / RuleVersions
```

Event ≠ Incident. One incident contains many events.

## 3. Evidence Model

Every evidence record keeps:

```text
source
timestamp
content reference
location (+accuracy + confidence)
extraction results
confidence
relationship to incident
```

## 4. Independent Evidence Count (Judge-Critical)

Dashboard must distinguish:

```text
Reports: 84
Unique devices: 31
Estimated victims: 46
Independent corroborations: 14
Confidence: 92%
```

100 messages ≠ 100 independent victims.

## 5. Synthetic Training/Test Data (MVP)

10,000 simulated disaster reports containing:

- Hindi, English, Hinglish, Marathi, Bengali, Tamil
- noisy SMS (typos, abbreviations)
- duplicate reports
- false reports / fake SOS bursts
- safe messages
- urgent medical cases
- stale reports
- inaccurate locations
- varying severity and vulnerability

Labelled ground truth for:

- incident classification
- severity extraction
- vulnerability extraction
- location extraction
- duplicate detection
- priority ranking

## 6. Location Data

Sources: GPS, AML/ELS, cell-derived, citizen coordinates, landmark descriptions, responder observations, simulation.

Every location carries:

```text
estimated location
accuracy / uncertainty
confidence
source
```

Location confidence model:

| Evidence | Confidence |
| -------- | ---------- |
| Exact GPS | High |
| AML/ELS | High |
| Cell-based location | Medium |
| Citizen-described location | Low |
| Landmark text inference | Low |
| Multiple independent reports agreeing | +confidence |

## 7. Signal Freshness

```text
FRESH / RECENT / STALE / UNKNOWN
```

- Freshness affects confidence.
- **Lack of new signals NEVER means victims are safe** (battery, network, unconscious, moved, rescued, SMS failed).

## 8. Retention

Configurable, aligned with government/legal/organizational policy. Team must not invent a universal retention period. Original evidence retained per policy for audit.

## 9. Data Portability

Core incident data uses documented schemas that can be exported. No vendor lock-in on emergency data.

## 10. Golden Data Rule

> **Never delete evidence, never conflate messages with victims, never present uncertain location as exact.**
