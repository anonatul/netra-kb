# NETRA — Rejected Ideas

> **File:** `26_rejected_ideas.md`
> **Status:** Living document
> **Version:** 1.0
> **Last Updated:** 2026-08-17
> **Purpose:** Record what was deliberately rejected and why, so the team never resurrects it or claims it.

---

## R-01 — "Phones automatically connect to our drone femtocell"

**Status:** 🔴 REJECTED (core MVP)

**Reason:** A random phone does not connect to an arbitrary rescue-team femtocell. SIM authentication, operator core integration, spectrum authorization, PLMN configuration, device selection, SMS routing, backhaul and lawful telecom operation are all involved. Not buildable with Docker + Bash. Judge: "architecture fantasy without a telecom partner and validated prototype."

**Allowed:** Tier-3 responder-side portable node as explicitly controlled experimental infrastructure only.

## R-02 — "2G always survives when 4G/5G fails"

**Status:** 🔴 REJECTED

**Reason:** A disaster can destroy tower power, backhaul, core network, radio equipment and transmission links. Dead tower = no 2G either.

**Allowed:** "NETRA operates under partial connectivity degradation with a fallback path for intermittent connectivity."

## R-03 — "No new distress ping = victims were rescued"

**Status:** 🔴 REJECTED

**Reason:** Silence can mean battery died, network disappeared, phone lost, person unconscious, SMS failed, tower failed, person moved — or rescue. Silence ≠ safety.

**Allowed:** freshness decays confidence; incident never auto-marks safe.

## R-04 — "Google Maps fails completely without 4G/5G"

**Status:** 🔴 REJECTED (as a claim)

**Reason:** Too simplistic and unnecessary; offline maps exist. Not a NETRA differentiator.

## R-05 — "NETRA works during complete cellular blackout"

**Status:** 🔴 REJECTED (as an MVP claim)

**Reason:** Ordinary SMS cannot be assumed to work without infrastructure. Complete RF isolation is a separate communication layer (radio/mesh/LoRa/satellite), experimental.

## R-06 — Kafka + RabbitMQ duality

**Status:** 🔴 REJECTED

**Reason:** One appropriate mechanism suffices for MVP; two brokers add operational complexity and failure modes without a measured requirement.

## R-07 — AI for simple keyword classification

**Status:** 🔴 REJECTED

**Reason:** "bleeding → medical-critical" doesn't need embeddings; deterministic rules are more reliable, explainable and auditable. AI only where it materially beats rules.

## R-08 — LLM in the emergency critical path

**Status:** 🔴 REJECTED

**Reason:** LLM failure must never suppress an emergency. LLM is optional Layer 3 with human-review-queue fallback.

## R-09 — Autonomous dispatch / auto-resolved incidents

**Status:** 🔴 REJECTED

**Reason:** Human accountability; AI detects → explains → dispatcher verifies → assigns → field executes.

## R-10 — Blockchain

**Status:** 🔴 REJECTED

**Reason:** No requirement it solves for the MVP; audit logs + protected append-only storage suffice.

## R-11 — Custom nationwide telecom network

**Status:** 🔴 REJECTED (MVP)

**Reason:** Massive cost/regulatory burden; NETRA is a software intelligence layer over existing infrastructure.

## R-12 — Fixed 50m DBSCAN radius

**Status:** 🔴 REJECTED

**Reason:** "Why 50m?" — arbitrary. Adaptive, uncertainty-aware clustering replaces it.

## R-13 — "NETRA invented dropped-call location" (AML)

**Status:** 🔴 REJECTED

**Reason:** Android ELS/AML already exists and is operational with UP 112. AML is an integration dependency, not innovation.

## R-14 — "NETRA replaces 112" positioning

**Status:** 🔴 REJECTED

**Reason:** False and self-defeating; ERSS is multi-channel with GIS dispatch. NETRA complements it as an intelligence layer.

## Golden Rejection Rule

> **A rejected idea stays rejected until a validated telecom partner, a working prototype or a measured requirement says otherwise.**
